# 리그 데이터 동기화

사용자가 제공한 엑셀 파일을 JSON으로 변환하고, 필요시 SEASONS 배열을 업데이트합니다.

## 입력

엑셀 파일 경로: $ARGUMENTS

## 실행 단계

1. **파일 존재 확인**: 제공된 엑셀 파일이 존재하는지 확인

2. **시즌 코드 추출**: 파일명에서 `YYYY-MM` 패턴을 찾아 `YYYYMM` 형식으로 변환
   - 예: `2026-01 리그 기록.xlsx` → `202601`
   - 예: `2026-01-recording.xlsx` → `202601`
   - `YY-MM` 형식이면 `20YY`로 보정: `26-10 리그 (2).xlsx` → `202610`

3. **JSON 변환 실행**:
   ```bash
   python3 convert_excel_to_json.py "<엑셀파일경로>" <시즌코드>
   ```

4. **새 시즌 확인**: index.html의 SEASONS 배열에 해당 시즌이 있는지 확인

5. **SEASONS 배열 업데이트** (새 시즌인 경우):
   - index.html에서 `const SEASONS = [...]` 부분을 찾아 새 시즌 코드를 배열 맨 앞에 추가

6. **라운드별 어워드 검증**: 스크립트 출력의 `반영 라운드`와 라운드별 MOM/더블더블을
   GBL 승점 시트 하단 라운드 표와 대조. 사용자가 스크린샷 등으로 기록을 따로 주면 그것과도 대조하고,
   다르면 `league_metadata_<시즌>.json`을 직접 보정

7. **결과 보고**: 이번에 반영된 라운드 전체(예: 2~3라운드)의 MOM·더블더블·득점왕, 팀 순위,
   홈 화면 표시 어워드를 보고. 이전 싱크 이후 라운드가 여러 개 늘었으면 그 사실을 명시

## 현재 라운드 판단 규칙

- **전체득점** 시트의 2행(첫 번째 선수 데이터)을 기준으로 판단
- n라운드 컬럼(D열~)에 값이 있으면 해당 라운드까지 진행된 것으로 판단
- 예: 1라운드, 2라운드 컬럼에 값이 있고 3라운드가 비어있으면 → 현재 라운드 = 2

## 여러 라운드 동시 업데이트 (중요)

싱크 한 번에 1라운드씩 증가한다고 가정하지 말 것. 이전 싱크 이후 여러 라운드가 한꺼번에 진행됐을 수 있다.

- **기준**: 기존 `league_metadata_<시즌>.json`의 `currentRound`(이전 싱크 라운드)와
  엑셀의 현재 라운드(전체득점 진행상황, GBL 승점 `N라운드 리그 누적 결과`)를 비교
  - 예: 기존 1라운드 → 엑셀 3라운드 = 2·3라운드 동시 반영
- **라운드별 어워드 원본**: GBL 승점 시트 하단의 `1 라운드 | 2 라운드 | ...` 표
  - 한 라운드 칸에 MOM/더블더블 셀이 여러 개(팀별 행) 있을 수 있음 → 모두 합침
  - `9명+ (승점 +1)` 같은 부가 줄, 줄바꿈으로 이어진 이름(`김돈규, \n김승민`) 처리
  - 상단 요약(`MOM: 김준환(2라), 강재훈(3라)`, `더블더블: X`)은 여러 라운드를 섞은 문구이므로
    라운드별 데이터로 쓰지 않는다
- **팀 성적**: `N라운드 리그 누적 결과` = 현재 라운드, `이전 라운드 누적 결과` = 직전 라운드
- **병합**: roundHistory는 기존 JSON과 라운드 단위로 병합 (이전 라운드 득점왕 등 엑셀에 없는 값 유지)
- **홈 화면 표시**: `updatedRounds`(이번 싱크로 반영된 라운드)가 2개 이상이면 `displayAwards`에
  `김준환(2라), 강재훈(3라)` 형식으로 합쳐 저장 → index.html이 이 값을 표시
  - 같은 라운드로 재싱크하면 기존 `updatedRounds` 유지

## 주의사항

- 파일명에 `YYYY-MM`(또는 `YY-MM`) 형식이 포함되어야 함
- convert_excel_to_json.py 스크립트가 프로젝트 루트에 있어야 함
- 엑셀 파일에는 '전체득점', '부가기록 계산', 'GBL 승점' 시트가 필요함
